# Components

Every view a plugin shows is a tree of components. Lua declares the tree with the builders of `workpane.ui`, the product validates every property strictly and draws the tree with Dear ImGui, and every interaction comes back to Lua as an event on the node that caused it.

The components gallery, a plugin off until the reader turns it on, shows each component below in every state, and its source in `plugins/components/views/pages` is a working example of each one.

## Building a tree

A builder takes a table of properties and, for a container, a list of children, while a container of fixed children takes them one by one after its properties, such as `ui.scroll(props, child)`, `ui.popover(props, child)`, `ui.splitter(props, first, second)`, `ui.formField(props, control)` and `ui.settingsRow(props, control)`:

```lua
local ui = workpane.ui

local name = ui.textField({ placeholder = text("sample.form.name"), width = 280 })

return ui.column({ padding = 24, spacing = 12 }, {
    ui.label({ text = text("sample.form.title"), style = "heading" }),
    name,
    ui.button({ text = text("sample.form.save"), variant = "primary", onClick = function()
        workpane.log.info("form", "Saved " .. name:get("value"))
    end }),
})
```

A property named `on` followed by a capitalized event name is a handler, so `onClick` answers the `click` event and `onRevealRequest` answers `reveal-request`. Handlers run in a task of the plugin, so they may await futures.

A node keeps the properties it was built with and those its events changed, which is why `name:get("value")` above answers what the reader typed.

| Method | What it does |
| --- | --- |
| `node:get(key)` | Answers the current value of a property |
| `node:set(properties)` | Changes properties and sends only what changed, and a handler given here replaces the previous one |
| `node:setChildren(children, properties)` | Replaces the children of a container, keeping every node already inside it with its state wherever it lands in the new children, such as a page loaded in a web view or a running terminal, and changes the properties given with them in the same step |
| `node:on(event, handler)` | Sets the handler of an event by its name |
| `node:command(name, arguments)` | Asks the component for something that is not a property, and a command sent before the node is mounted reaches it right after its mount, in the order it was sent, where a command that needs the first draw of its component, such as the navigation of a web view or the copy of a terminal, is refused with the error of that component |

A patch the product refuses leaves the node exactly as it was, because every patch is read into the node, proven against all of its properties and its children and put back whole when any check refuses it, so a stack refuses a page it does not hold and a strip of tabs with pages refuses tabs without a page of their own. An event that changes what its node shows, such as a new value, check, selection, ratio, zoom or tab order, changes the node on the Lua side as well, so `node:get` answers what the reader left on screen. A surface nests at most 64 levels below its root and carries fewer than 50000 nodes, counted over the whole surface when children are replaced, so a tree mounted or grown past either bound is refused with `ui_tree_too_deep` or `ui_tree_too_large`.

## Common properties

Every component accepts these properties.

| Property | Type | Meaning |
| --- | --- | --- |
| `visible` | boolean | Hides the component and removes it from the layout |
| `enabled` | boolean | Disables the component and everything inside it |
| `tooltip` | text | Shows a tooltip after the pointer rests on the component, in the dark panel of the theme and inside the window, and none while the keyboard navigates until the pointer moves again |
| `grow` | number | Shares the free space of the parent row or column by this factor |
| `collapse` | integer from 0 to 100 | Hides the child when its row lacks room for every child, the highest number first, and 0 never hides it |
| `width`, `height` | number or `"auto"` | Fixes the size in points, so a component given a width keeps it in a column or a form field instead of stretching |
| `minWidth`, `maxWidth`, `minHeight`, `maxHeight` | number | Bounds the size, including the size growth assigns and the size a stretched component takes across its parent |
| `align` | `start`, `center`, `end` or `stretch` | Places the component across the axis of its parent |
| `menu` | list of menu items | Opens a menu under the pointer on a secondary click and reports the `menu` event with the `item` picked |
| `drag` | table with `kind`, `value` and `label` | Lets the reader drag the component to a target that accepts its kind |
| `accepts` | list of kinds | Receives a dragged value of one of these kinds and reports the `drop` event with its `kind` and `value` |

Growing children share the free space of a row or a column by their factors. A shortfall a growing child of a column cannot give back past its minimum passes to the other growing children, while room a growing child cannot take past its maximum stays free. A component given less than a pixel in either direction draws nothing.

A menu item has the shape the menu button uses. When components with menus are nested, the innermost one under the pointer opens its menu, and a disabled component opens none.

A drag kind is a dotted name of lowercase letters, numbers and hyphens, such as `terminal.session`, and the `value` is any value the target should receive. The drag starts once the pointer travels past the drag threshold, so a click on the same component still clicks it, and the `label` is carried beside the pointer while it moves. The innermost enabled component under the pointer that accepts the kind is outlined in the accent, and it reports `drop` when the pointer lets go over it. Escape abandons the drag, and a component never receives its own value.

## Texts, colors and icons

A text is either a literal string or a translation reference built with `workpane.i18n.text(key, ...)`. A reference is resolved again whenever the reader changes the language, so views never rebuild for it.

A color is a theme role named in kebab case, and the roles come in families so a plugin always finds the color made for its case:

| Family | Roles |
| --- | --- |
| Surfaces | `window`, `panel`, `raised`, `terminal`, `tooltip` and the translucent `overlay` that dims the window under a dialog |
| States | `hover`, `pressed`, the translucent `selection` of selected text, the translucent `highlight` of a found match, and `focus`, the border of the control that has the keyboard |
| Borders and scroll bars | `border`, `border-strong`, `scrollbar`, `scrollbar-hover` and `scrollbar-active` |
| Text | `text`, `text-muted` and `text-disabled` on the window, and `on-tooltip` and `on-tooltip-muted` on the tooltip |
| Accent | `accent`, `accent-hover`, `accent-strong`, the ink `on-accent` written over those fills, the subtle `accent-background` and the readable `accent-text` |
| Success, warning and information | The fill named by the tone, the ink `on-success`, `on-warning` or `on-information` written over it, the subtle background such as `warning-background` and the readable text such as `warning-text` |
| Danger | `danger`, `danger-hover` and `danger-strong` for destructive buttons, the ink `on-danger`, `danger-background` and `danger-text` |

Text written over a fill takes the ink of that fill, never the text color of the window, so a label on yellow is written in `on-warning` and a label on red in `on-danger`. A tone text such as `danger-text` stays readable on the window and on the background of its tone, and every theme is tested for the contrast of each pair. A fill darkens under the pointer in its hover role and further in its strong role, so its ink reads at least as well as on the fill at rest, while a link lightens toward the readable text of its tone. The word `none` clears an optional color. The complete list is also available at run time as `workpane.app.colors`, and the Theme Colors page of the gallery shows every role with the ink written on it.

An icon is a glyph of the bundled Lucide font, named either by the product, such as `add`, `terminal` or `settings`, whose list is available as `workpane.app.icons`, or by its Lucide name, such as `bird`, `swords` or `gamepad-2`, and a name the product gives wins over the Lucide glyph of the same name. The Icons page of the gallery shows both. A name the font does not know is refused with `ui_icon_unknown`, and the word `none` clears an optional icon. Its `size` is the side of the square its glyph fills.

A font size, such as the `size` of a label or the `fontSize` of Markdown, a code editor or a terminal, is an em size in points, the size every other text renderer means. Every reading size a reader chooses starts at 11 points, and the zoom reset key of a code editor or a terminal takes it back there.

The `fontFamily` of a code editor or a terminal names a monospaced family of the machine, or `JetBrains Mono` for the bundled face, which is the default. The family is read in the background and drawn from the frame after, and one the machine lacks or cannot read is drawn in the bundled face. An empty name or one longer than 256 bytes is refused with `editor_font_family_invalid` or `terminal_font_family_invalid`.

A tone is one of `neutral`, `accent`, `success`, `warning`, `danger` and `information`, and each one brings its family of colors: a fill, the ink written over it, a subtle background and a readable text color. The neutral tone fills with the muted text color and lies on the pressed surface.

## Layout

Rows and columns place children along their axis. Children that do not grow keep the size their content asks for, and growing children share what is left by their factors. When a column is shorter than its content, its growing children give the difference back, down to their minimum height, which is how a scroll area fills the space above a fixed footer. A row or column that grows nothing justifies its children instead. A row without room for every child at its content width and every growing child at its minimum width hides the children with a `collapse` above zero, the highest first, until the rest fits, which is how a header gives up its details and then its buttons as it narrows.

| Kind | Properties | Children |
| --- | --- | --- |
| `column` | `padding`, `spacing`, `justify`, `background`, `borders` | Any number |
| `row` | `padding`, `spacing`, `justify`, `background`, `borders` | Any number |
| `card` | The properties of a column plus `title`, `icon`, `outline` and `radius` | Any number |
| `grid` | `columns` from 1 to 24, `columnSpacing`, `rowSpacing`, `padding` | Any number, filled row by row |
| `stack` | `current`, the index of the child shown | Any number |
| `scroll` | `padding`, `follow`, `orientation` | Exactly one |
| `splitter` | `orientation`, `ratio`, `firstMinimum`, `secondMinimum` | Exactly two |
| `spacer` | None | None |
| `divider` | `orientation` | None |

A splitter whose pane is hidden gives the whole rectangle to the other pane and draws no handle, which is how a side panel opens and closes. A splitter that does not grow stands as tall as its minimums and its handle when its panes are stacked, and as tall as its taller pane when they sit side by side. Padding is one number, two numbers for vertical and horizontal, or four numbers for top, right, bottom and left. The justification is `start`, `center`, `end` or `space-between`. Borders are a list of sides, and each one is drawn as a single thin line. A step of the wheel or of the trackpad scrolls every view as far as the system scrolls its own, ten points on macOS and three lines of text for each notch on Windows and Linux, and a sideways scroll area or a strip of tabs that can move takes the wheel from the view around it, so a turn over it moves it alone. A scroll area that `follow`s keeps the bottom in view while its content grows, as long as the reader stays near the bottom, which is how a conversation or a log follows what arrives. A scroll area with the `horizontal` `orientation` measures its content at its own width, so children of a fixed width overflow it while growing and filling children take its width, grows by its scroll bar when that content overflows and turns the wheel into sideways movement of the same distance, which is how the shelf of the Terminal plugin keeps every terminal within reach.

| Kind | Events | Commands |
| --- | --- | --- |
| `splitter` | `resize` with `ratio` | None |
| `scroll` | `top` when the reader arrives at the top of content taller than the area | None |
| `card` | `activate` on a double click outside its controls, from the innermost card under the pointer | None |

## Text

| Kind | Properties | Events |
| --- | --- | --- |
| `label` | `text`, `style`, `color`, `size`, `textAlign`, `wrap`, `selectable` | None |
| `pageHeader` | `title`, `caption`, and the actions of the page as children | None |
| `sectionTitle` | `text`, written in upper case in the accent | None |
| `emptyState` | `text`, `icon` | None |
| `alert` | `text`, `tone` | None |

A label style is `body`, `strong`, `muted`, `caption`, `title`, `heading` or `monospace`. A label that does not wrap shows one line, so text after a line break or past its width is left out and marked with an ellipsis. An alert states something the reader must see on the background of its tone, in the text color of that tone and with one rule of two points in the tone down its left edge, and a plugin shows and hides it with `visible`. Its `tone` is danger when it names none, since most alerts report a problem, and a warning, a success, an information, the accent or a neutral note take their own families. An alert that a patch shows or rewrites after it was mounted scrolls itself into view, so a problem reported at the end of a long form is seen at once. The Markdown component reads headings, paragraphs, emphasis, strong text, inline code, fenced code, links, bullet and numbered lists with nesting, quotes and rules. A link is reported rather than opened, so the plugin decides where it goes. With `breaks` every line break inside a paragraph is kept where it was written, which is how a chat reads.

An option is a table with `value` and `text`, and a value names something, so it is never empty. A secret field that confirms its reveal reports `reveal-request` and shows the secret only when its owner sets `revealed`. A date is written `YYYY-MM-DD` and a date with time `YYYY-MM-DD HH:MM`, in local time. A color is a number sign followed by six hexadecimal digits.

A row carries `id`, `cells` and the optional `actions`, where a cell is a string or a table with `text` and the optional `icon`, `muted`, `monospace` and `tone`, and an action carries `id`, `icon` and the optional `tooltip`, `destructive` and `tone`.

| `webView` | `url`, `html`, `popup` | `navigation` with `url`, `title`, `icon`, `loading`, `canGoBack` and `canGoForward`, `open-request` with `url` and `background`, `popup` with `popup`, `close-request`, `download` with `path`, `finished` and `message`, `permission-request` with `request`, `origin`, `camera` and `microphone`, `error` with `code` and `message` | `navigate` with `url`, `reload`, `back`, `forward`, `stop` and `answer-permission` with `request` and `allowed`, each refused with `webview_unavailable` until the native view exists at the first draw |
| `terminal` | `directory`, `shell`, `historyFile`, `palette`, `fontSize`, `fontFamily`, `history`, `clipboardWrites`, `cursorBlink` | `title` with `title`, `directory` with `path`, `bell`, `notification` with `title` and `body`, `exit` with `code`, `link` with `url`, `zoom` with `fontSize`, `find` with `count`, `current` and `bounded`, `focus` with `focused`, `error` with `code` and `message`, `input-refused` | `copy`, `paste`, `clear` and `find` with the optional `text`, `caseSensitive` and `wholeWord`, each refused with `terminal_not_running` before the first draw, `restart`, `focus` |

The code editor reports its text a quarter of a second after the first edit it has not reported yet rather than on every keystroke, and answers the zoom keys while it has the keyboard. A `value` from the plugin is kept exactly as written, tabs included, while the tab key inserts spaces when `insertSpaces` asks for them, and it is never reported back with `change`. An editor that is not enabled is read only and offers no menu, completion, definition or zoom. Lines and columns are counted from one, and a column counts characters. Its `language` is one the library carries, `none`, `c`, `cpp`, `cs`, `angelscript`, `lua`, `python`, `glsl`, `hlsl`, `json`, `markdown` or `sql`, or a definition with `name` and the optional `caseSensitive`, `lineComment`, `lineCommentAlternative`, `blockComment` with `start` and `end`, `singleQuotes`, `doubleQuotes`, one character of `escape` and of `preprocessor`, the word lists `keywords`, `declarations` and `identifiers`, whose words, numbers and punctuation are read the way C reads them, and the `constructs` it colors beyond words: `markdown` for the headings, emphasis, code and links of Markdown, `decorators` for an at sign followed by a dotted name, and `tags` for the tags of markup like keywords with their attributes like declarations.

A `scheme` names every color of the editor as a number sign followed by six hexadecimal digits: `text`, `keyword`, `declaration`, `number`, `string`, `punctuation`, `preprocessor`, `identifier`, `knownIdentifier`, `comment`, `background`, `cursor`, `selection`, `lineNumber`, `currentLineNumber`, `guide`, `activeGuide`, `currentLine` and `occurrence`, where the guides color the lines that join a pair of brackets, `currentLine` fills the line of the cursor under its text on every row it wraps to while nothing is selected, and `occurrence` tints the other uses of a symbol. A pair of brackets draws its line only beside the lines indented past it, as the indent guides of Visual Studio Code, so a block whose body is not indented, such as a namespace, draws none, and a blank line counts as indented as its neighbors are or just past the shallower one. Rows are one and a half em tall rounded to a whole pixel with their text centered, as Visual Studio Code draws them on macOS, and the gutter holds a glyph margin of three glyphs, the numbers right aligned and centered in their rows, and one glyph before the text. Without `lineNumbers` the gutter goes away with its glyph margin, and the markers show only as their underlines. Without a scheme the editor uses Dark Modern, the default theme of Visual Studio Code, over the window color of the theme. The caret is a bar as wide as the caret of the theme that blinks from the moment it last moved. A marker carries `line`, a `tone` of `danger`, `warning` or `information` and a `message`, and may carry the `column` it starts at with the `endLine` and `endColumn` it stops before, a muted `detail` such as the origin and code of a problem and a list of `related` places, each with a `place` and a `message`. Positions count from one, a marker without a column covers its whole line, an empty range covers the word at its start, and a marker whose end comes before its start or that names an end without a column is refused with `editor_marker_range`. A marker draws a wavy underline in its tone under its range, a marker of a whole line underlines the text after its indentation, an empty range underlines the word at its start or one glyph, and a stronger tone wins where two overlap, while no line is tinted and no number is boxed. The glyph margin shows the icon of the strongest tone among the markers starting on a line, one em tall, and resting the pointer on that icon or on the number lists all of them in one tooltip, while resting it on the text lists only the markers covering that glyph. Each marker in the tooltip shows the icon of its tone, its message in the tooltip ink, its detail beside its line and column and its related places in the muted tooltip ink, with a divider between markers, as the hover of Visual Studio Code does. A highlight carries `line`, `column`, `length` and a `role` among the first ten colors of the scheme, or it is refused with `editor_highlight_invalid`, and it colors that range over the colors of the language until the plugin sends other highlights, which color the pairs of brackets again too.

With `completion` the editor asks for proposals with `complete-request` as the reader types a word, types one of the `completionTriggers` or presses control and space, and `suggest` answers that `request` with the proposals the plugin found under the cursor, each with a `label`, the text it will `insert` and the optional `detail`, `documentation` and `range` it replaces. The list narrows to what the reader keeps typing, the arrows and the page keys choose, Enter or Tab accepts, a click accepts the proposal clicked, Escape closes it, and the documentation of the chosen proposal stands beside the list. An accepted proposal replaces its range, stretched to the cursor when the reader typed past it, or the word under the cursor. Only the latest request is answered, and only once, so proposals for an older request, proposals that arrive after the list closed and proposals that arrive after the cursor left their word are dropped. The list keeps the proposal the arrows chose while the word does not change, and a proposal whose range the cursor no longer ends or the document no longer holds is never written. With `hovers` the pointer resting on a word reports `hover` once, and `hover-text` shows the text the plugin found for that position while the pointer stays there, below the markers covering it in the same tooltip. The editor reports its text with `change` a quarter of a second after an edit, and `flush` reports an edit that delay still holds at once and then answers `flushed`, so a plugin saves or closes with the text on screen. An editor that is no longer drawn reports the edit it held at once as well. A new `value` from the plugin keeps the cursor, the selection and the first visible line where the reader had them, as far as the new text reaches. A decoration carries `line`, `column`, `endLine`, `endColumn` and a `style` of `occurrence`, which tints the other uses of a symbol in the occurrence color of the scheme, `faded`, which covers code that has no effect halfway with the background, or `struck`, which crosses code no longer to be used. With `definitions` a click on the text while `mod` is down reports `definition-request` for the clicked position instead of adding a cursor. A secondary click moves the caret where it landed, unless it landed in the selection, and opens Undo, Redo, Cut, Copy, Paste and Select All followed by the `menu` of the plugin, whose pick is reported with `menu`. On macOS Command with the left or the right arrow moves to the start or the end of the line and selects up to there with Shift, as every text view of macOS does, and Command with the up or the down arrow moves to the start or the end of the text. Mod F while the editor has the keyboard opens the find bar of the product over its top right corner from the selected text of one line, with the count of the matches, match case, whole words and the steps between matches, which Enter, shift Enter and the find keys of the platform take too, and Escape closes it. A writable editor adds a row that replaces the match being read or every match in one step of the undo history, and an edit made while the bar is open finds the matches again so a replacement never lands on text that moved. The bar takes the pointer where it covers the text, so a tooltip, a menu or a definition click never answers through it. The `cursor` event reports the line and column of the cursor whenever it moves, with the selected text when the selection stays inside one line. `reveal` puts the cursor on a position, scrolls it to the middle and gives the editor the keyboard.

The terminal runs the shell of the reader in its `directory` behind a pseudo-terminal and draws it with libvterm. The shell reads the startup files it reads in a terminal of its system: on macOS it starts as a login shell, as Terminal starts it, so zsh reads `.zshenv`, `.zprofile`, `.zshrc` and `.zlogin` and bash reads `.bash_profile`, and on Linux it starts as an interactive shell, so zsh reads `.zshenv` and `.zshrc` and bash reads `.bashrc`. On Windows PowerShell 7, or Windows PowerShell when it is the only one, loads the profiles of the reader, the command prompt runs its AutoRun command, and a POSIX shell such as Git Bash starts as an interactive login shell, as Windows Terminal starts it. A `shell` names the absolute path of another shell to start instead, and a `historyFile` gives POSIX shells a history of their own through `HISTFILE`, with zsh reading it through startup files written beside it that load the files of the reader first and give the reader back its own `ZDOTDIR`. A new history starts with the commands of the history of the reader, for zsh, bash and PowerShell alike, and a history of the reader that cannot be read leaves the new one empty. A shell never receives what a terminal of Workpane exported for its own shell, so a product started from such a terminal leaves out the `WORKPANE_` variables and the `HISTFILE` of that terminal, and a `ZDOTDIR` naming its integration folder gives way to the folder of the reader it recorded. The `palette` is `vivid`, `balanced` or `soft`, the `history` keeps up to that many lines above the screen and `clipboardWrites` lets a program write to the clipboard. The cursor stays steady unless `cursorBlink` gives the milliseconds it stays lit and then dark, from 100 to 2000, and a shorter interval is refused with `terminal_blink_invalid`. A blinking cursor blinks only while the terminal has the keyboard and its program did not ask for a steady one, starts lit again at every key and stays lit once the keyboard rested for fifteen seconds, so an idle window stops drawing. Every character takes the width the shell behind it gives it, the width of the C library on macOS and Linux and of the Unicode tables on Windows, so the line editor of the shell and the screen agree on every column. Every glyph sits on its own cell of whole points, and a line is as tall as the face, which is what box drawing characters join across. Faint text is drawn halfway between its color and its background. A click gives it the keyboard, and it keeps every key while it has it except the product combinations, which are Command on macOS and control with shift elsewhere: copy, paste, select all, clear and find answer there, and copy on Windows is the plain control combination while something is selected. It never keeps the pointer, so any other control answers the first click while the terminal has the keyboard. It reports the `directory` the shell stands in, a `notification` a program sends with the ninth or the 777th operating system command, a `link` when the reader clicks a web or file address with `mod` even while the program has the mouse, whether the address is written out or is the hidden address of a hyperlink the program wrote with OSC 8, `input-refused` once when the shell has not read the input already waiting for it, and `exit` after the last output of its program, and when it is detached it hangs up its shell and ends it in the background, killing after half a second a shell that ignores the hangup, so closing a terminal never waits for its shell and the product waits for the shells still ending only as it quits. A program that asked for the mouse receives the left, middle and right buttons as themselves and one report for every three lines the wheel moves on either axis, which is one notch on Windows and Linux, and without such a program the wheel scrolls the history as far as it scrolls any view, keeping what a trackpad moved less than a line until it adds up to one. A secondary click on a terminal whose program did not ask for the mouse opens Copy, Paste, Select All and Clear. A double click selects a word, a triple click the whole line the program wrote and a drag with alt a rectangle. The line edits follow the terminal of each system: on macOS Command with the left or right arrow goes to the start or the end of the line, Command with backspace or delete erases to its start or its end, Option with the arrows or delete moves or erases a word, and Command with the up or down arrow, Page Up, Page Down, Home and End moves through the history, while on Linux control with the arrows or delete moves or erases a word and control with backspace erases the word before the cursor, and Windows hands every key to its console as it is. A held key repeats at the delay and the rate the reader set in the system, and every repeat that arrives within one frame reaches the program. Shift with Page Up, Page Down, Home and End moves through the history and shift with insert pastes, the find keys of the platform, mod G or F3 with shift going back, step through an open search, and opening find with its shortcut starts from the selected text of one line. A search or a step selects the match it reaches and brings it into view, while new output only moves the marks and the count, so the view and the selection stay where the reader left them. The find bar takes the pointer where it is drawn, so a click on it never reaches the program. The scroll bar along the right edge is dragged by its thumb, and a click on its track brings the thumb under the pointer. Output is read in slices of 128 kilobytes each frame, and the shell is no longer read while a megabyte waits, so a flood holds back the program rather than the window. Files dropped on it from the system are written to the shell as their quoted paths, and a drop naming a path with a control character writes nothing. `restart` starts a new shell in the last directory.

The web view is a native view of the operating system placed over its rectangle, which is WebKit on macOS, WebView2 on Windows and WebKitGTK on Linux. It hides itself while a product dialog is open, because a native view is drawn above everything the product draws, and it cuts out the tooltips, menus, lists and notifications the product draws over it, so they show and take the pointer there. It reports `navigation` whenever the address, the title, the loading or the history of its page changes, as the engine of the platform tells it, and with the icon the page draws as a PNG data address once the page script drew it, which a page of another site starts without. A link the reader opens with the modifier of new tabs or the middle button reports `open-request` with `background` set, so the plugin opens the address behind the active tab. A page that opens a window, such as the sign in window of a service, reports `popup` with a number, and a web view mounted with that number as `popup` shows the window, which keeps its opener, so the page and the window talk to each other, and whose first document already runs the page script of the view. A window nobody adopts within a few frames is closed, and a web view naming one that is gone reports `error` with `webview_popup_missing`. A page asking to close its window reports `close-request`. A page behind another tab reports as soon as a page on screen does. A web view shows one of an address, a document or a window, and two of them are refused with `webview_content_ambiguous`. An address given as `url` or to `navigate` names the web, a file or an about page, and any other is refused with `webview_address_invalid`, while navigating leaves the declared content as it was. A web view that could not be built shows a translated message in its rectangle and reports `error` with the code once, whether it failed at once or while its page was built in the background, as WebView2 builds every page on Windows, and answers no command afterwards.

A page reads a user agent that names the browser of its engine with its version, as sites expect of a current browser: Safari with the version installed on macOS, where WebKit leaves the browser out for an application, and the agents WebView2 and WebKitGTK already send on Windows and Linux. A page may show an element in full screen, such as a video player, on every platform.

A response the page cannot show, one sent as an attachment and a link marked for download are saved in the downloads folder of the reader under the name the page suggests, with a counter before the extension while a file of that name exists, and the view reports `download` with the `path` written with forward slashes once it `finished`, or with `finished` false and the `message` of the engine when it failed.

A page asking for the camera or the microphone is answered by the prompt of WebKit on macOS and of WebView2 on Windows, and on Linux, where WebKitGTK asks nobody, the view reports `permission-request` with a `request` number, the `origin` of the page and what it asks for, and waits until the owner sends `answer-permission` with that number and whether it is `allowed`. A request answered twice or no longer waiting changes nothing, and a view that goes refuses what still waits. The macOS bundle says why it uses the camera and the microphone, which macOS shows the reader before either is used. WebRTC works wherever the engine carries it, which the WebKitGTK of some distributions, Ubuntu among them, does not.

Passkeys and security keys work in the web view on Windows. On macOS WebKit answers them only in an application Apple grants the entitlement of web browsers, so they work in a web view of Workpane only once that entitlement is granted and signed into the bundle.

## Canvas

| Kind | Properties | Events | Commands |
| --- | --- | --- | --- |
| `canvas` | `frameRate` from 0 to 120, `pixelated`, `focusable`, `tracking`, `background`, `pictures` | `frame` with `delta`, `time`, `width` and `height`, `layout` with `width` and `height`, `pointer-down` and `pointer-up` with `x`, `y` and `button`, `pointer-move` with `x` and `y`, `wheel` with `x`, `y`, `deltaX` and `deltaY`, `key-down` and `key-up` with `key`, `focus` with `focused`, `image-error` with `image` and `message` | `draw` with `commands`, `focus` |

A canvas is a surface its plugin draws on, which is what games, charts and drawings are made of. It takes the width it is given and stands 200 points tall until its plugin gives it a `height` or lets it grow, and its `background` is a color or `none`, the default. Every position and size is in points from the top left corner of the canvas, so a drawing keeps its size on every density.

The `draw` command replaces the whole list the canvas draws, which it keeps drawing on every frame until the next list arrives. A list holds at most twenty thousand commands and a longer one is refused with `ui_canvas_list_too_long`. Each command is a table whose `op` names what it draws and that carries only the fields of its operation, and a command with an unknown field, a missing field, a value out of range or a color it cannot read refuses the whole list with `ui_canvas_command_invalid` and the index of the command in the detail, so the list on screen stays as it was.

| `op` | Fields |
| --- | --- |
| `rect` | `x`, `y`, `width`, `height` and `color`, and the optional `opacity`, `radius` of its corners, `filled`, true unless it is false, and the `thickness` of its outline |
| `line` | `x1`, `y1`, `x2`, `y2` and `color`, and the optional `opacity` and `thickness` |
| `circle` | `x` and `y` of its center, `radius` and `color`, and the optional `opacity`, `filled` and `thickness` |
| `image` | `image`, a plain path inside the `assets` folder of the plugin, `x`, `y`, `width` and `height`, and the optional `source` with `x`, `y`, `width` and `height` in pixels of the picture, `tile` with the `width` and `height` in points at which the picture repeats across the rectangle, `flipX`, `flipY`, `rotation` in radians around its center and `opacity` |
| `text` | `x`, `y` of its top and `text`, a literal or a translation reference, `color`, and the optional `size` in points from 6 to 128, `face` of `regular`, `semibold` or `monospace`, `align` of `start`, `center` or `end` around `x`, and `opacity` |
| `clip` | `x`, `y`, `width` and `height` of the region every later command stays inside until `unclip` |
| `unclip` | None |

A color is a role of the theme, drawn in the theme the reader chose, or a literal written with a number sign and six hexadecimal digits, because what a plugin draws on a canvas is its own content, and `opacity` from 0 to 1 fades it. A source rectangle draws one frame of a sprite sheet, so an animation is one picture and a list of rectangles, and the frame is sampled a sixty-fourth of a pixel inside its edges in a pixelated canvas and half a pixel inside in any other, so the frame beside it never shows along an edge that lands on the center of a pixel. A tiled picture repeats from the corner of its rectangle at the size of its tile, one or more points on each side, and is cut at the far edges, so a floor or a wall of any length is one command. A tiled picture never turns and repeats at most 4096 times, and a command breaking either rule is refused. A picture is decoded in the background and drawn from the frame it is ready, and one that cannot be read is reported once with `image-error`. The `pictures` a canvas names, at most 256 paths inside the assets of its plugin, are held from the frame it mounts, so each one is decoded before the first frame that draws it and stays while the canvas does, and they are let go when the plugin names others or the canvas leaves, as it does when its plugin turns off. A picture outside the assets refuses the canvas with `ui_canvas_picture_invalid`, and a longer list with `ui_canvas_pictures_too_many`. A game names every sheet it draws, so no figure is missing while its sheet is decoded the first time it shows. A `pixelated` canvas samples its pictures by the nearest pixel, so pixel art stays sharp at any scale, while every other picture of the product stays smooth.

A canvas with a `frameRate` reports `frame` that many times a second while it is drawn, with the seconds since the last one bounded to a quarter of a second, the time and its size, and asks the frame loop for its next tick instead of keeping it awake. A plugin answers each frame with a new list, which the canvas draws in the next one. A canvas in a view off screen, in a band the reader hid or in a minimized window reports nothing, so a game pauses by itself. A rate of zero, the default, reports no frame, and the canvas then draws only when its list changes.

The canvas reports `pointer-down` and `pointer-up` with the position and the `button`, which is `left`, `right` or `middle`, and `wheel` with the position and how far the wheel scrolls on each axis in points, positive toward the right and the bottom, while the pointer is over it, and `pointer-move` with the position on every frame the pointer moves over it while it is `tracking`. It reports `layout` with its size in points whenever that size changes. A `focusable` canvas takes the keyboard on a click and on the `focus` command, reports `focus` when it takes or loses it, and reports `key-down` and `key-up` with the name the shortcut grammar gives the key, such as `space`, `up` or `a`. It keeps every key while it has the keyboard, so no other control answers them, except the combinations of the product, which still quit, open the settings and move between destinations, and when it loses the keyboard it reports `key-up` for every key it told as held before it reports `focus`.

## Forms

| Kind | Properties | Children |
| --- | --- | --- |
| `formField` | `label`, `hint` | Exactly one control |

A form field writes its label above its control followed by a colon, so a label of any length never decides the width of its control. A control that stretches takes the whole width under the label and any other keeps its own width, so a field beside another in a row is only as wide as its control or its label. A hint sits under the control in the caption face. The forms of dialogs are columns of form fields, while the settings view keeps its rows with the caption on the left.

## Settings

| Kind | Properties | Children |
| --- | --- | --- |
| `settingsForm` | None | Settings rows and actions |
| `settingsRow` | `label`, `hint` | Exactly one control |
| `settingsActions` | None | Buttons, placed inside a settings form whose inset they take |

Every settings section is built from these three, so every owner produces the same shape with the same insets as the core settings. A settings row writes its caption on the left and places its control against the right edge, and its hint sits under the control in the caption face, wrapped within the readable width with every line ending where the control ends.
